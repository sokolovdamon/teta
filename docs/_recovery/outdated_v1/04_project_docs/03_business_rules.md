# Бизнес-правила платформы ТЕТА

> Версия 1.0 · 11.09.2026 · Статус: черновик на утверждение
> Бизнес-правило (`BR-<область>-NN`) — правило предметной области, которое система обязана соблюдать независимо от интерфейса. Правила с пометкой **[допущение]** опираются на рекомендацию аналитика и должны быть подтверждены заказчиком (см. связанный Q).
> Все числовые значения вынесены в **параметры** (раздел 1) и настраиваются администратором без доработки кода.

> ⚠️ **Правовые оговорки по итогам исследования** ([research_legal_integrations.md](../99_sources/research_legal_integrations.md)) — действуют поверх правил ниже до заключения юриста:
> 1. **ЗоЗПП ст. 32:** потребитель вправе отказаться от услуги в любое время, оплатив только фактически понесённые расходы; заранее определённый размер удержания может быть признан ничтожным. Поэтому BR-CANC-02, BR-CANC-03, BR-CANC-04 с удержанием 100 % после списания — **зона риска**. Рабочая рекомендация до решения юриста: после списания — бесплатный перенос (1 раз) и частичный возврат, а удержание обосновывать зарезервированным временем специалиста (Q-33).
> 2. **152-ФЗ в ред. 156-ФЗ (с 01.09.2025):** согласие на обработку ПДн оформляется отдельно от оферты; для сведений о здоровье — письменная форма, допустим электронный документ, подписанный простой электронной подписью (код подтверждения). См. BR-ACC-09 и Q-34.
> 3. **376-ФЗ (с 01.03.2026):** после отказа потребителя от использования карты платежи по ней запрещены; отказ принимается и в электронной форме. См. BR-PAY-11.
> 4. **Дзен:** `canonical` на сайт в импортированной статье поставить нельзя — статья сначала публикуется на сайте, в RSS для Дзена попадает с задержкой. См. BR-CONTENT-06.
> 5. **ЗоЗПП ст. 16:** согласия на маркетинг, аналитические cookies и публикацию отзыва не могут быть условием получения услуги.

### Дополнительные правила по итогам юридического исследования

|---|---|---|

## 2. Аккаунт и доступ (`BR-ACC`)

| ID | Правило | Связанные разделы |
|---|---|---|
| BR-ACC-01 | Учётная запись идентифицируется email. Один email — одна учётная запись на тенант (для white-label — отдельно по тенантам) | WIZ-05, X-01 |
| BR-ACC-02 | Email подтверждается вводом одноразового кода или переходом по ссылке. Неподтверждённый email не позволяет привязать карту и забронировать сессию, но позволяет пройти анкету и увидеть подбор | WIZ-05 |
| BR-ACC-03 | Клиент вправе использовать псевдоним вместо имени. Реальное имя не требуется для получения услуг [допущение: уточнить требования к чекам и договору — Q-06] | CL-08 |
| BR-ACC-04 | Услуги оказываются только лицам 18+. Возраст подтверждается заявлением пользователя при регистрации (Q-30) | WIZ-02a |
| BR-ACC-05 | Одна учётная запись может иметь несколько ролей (например, психолог, который сам проходит терапию у коллеги) только с раздельными профилями; психолог не может записаться к себе | X-01 |
| BR-ACC-06 | Психологи, администраторы, HR-пользователи и пользователи кабинета партнёра обязаны использовать двухфакторную аутентификацию | X-01 |
| BR-ACC-07 | При удалении аккаунта: доступ блокируется сразу; будущие сессии отменяются по правилам отмены клиентом; ПДн удаляются или обезличиваются в течение `P-DELETE-GRACE`, кроме данных, срок хранения которых установлен законом (финансовые документы) | CL-08, ADM-02 |
| BR-ACC-08 | Отзыв согласия на обработку сведений о состоянии здоровья прекращает использование анкеты, дневника и подбора; такие данные удаляются. Продолжение консультаций само по себе связано с обработкой сведений о здоровье (факт работы с психологом, заметки) — порядок определяет юрист; до его решения клиенту предлагается выбор: сохранить согласие в минимальном объёме (только проведение сессий) или завершить работу и удалить аккаунт [ЮРИСТ] | CL-08, Q-34 |

## 3. Подбор (`BR-MATCH`)

| ID | Правило |
|---|---|
| BR-MATCH-01 | Подбор выполняется по анкете или итоговой карточке диалога с Германом, подтверждённой клиентом. Неподтверждённый итог бота не используется |
| BR-MATCH-02 | В подборку попадают только психологи со статусом «Активен», не находящиеся в отпуске ближайшие `P-MATCH-AVAILABILITY-DAYS` дней, с хотя бы одним свободным слотом в горизонте записи |
| BR-MATCH-03 | Факторы ранжирования: совпадение тем (вес максимальный) → соответствие предпочтениям (пол, метод, формат, уровень) → наличие слотов в предпочитаемое время → внутренние показатели качества (удержание клиентов, приватные оценки) → равномерность загрузки. Веса настраиваются в ADM-05 и описываются в публичных правилах рекомендательных технологий |
| BR-MATCH-04 | Клиенту показываются причины рекомендации текстом; числовые рейтинги и индексы не показываются (Бриф 8.4, Q-09) |
| BR-MATCH-05 | Повторное анкетирование доступно в любой момент; новая анкета заменяет прежнюю для подбора, прежняя хранится в истории |
| BR-MATCH-06 | Кризисные признаки в анкете или диалоге с ботом не блокируют подбор, но всегда показывают ресурсы экстренной помощи и фиксируются как флаг для кризисного протокола (`BR-CRISIS`); порядок подбора при кризисных признаках — Q-41 |
| BR-MATCH-07 | AI-помощник не даёт психологических рекомендаций, не ставит диагнозы и представляется как AI в начале каждого диалога |

## 4. Расписание (`BR-SCHED`)

| ID | Правило |
|---|---|
| BR-SCHED-01 | Все даты и время хранятся в UTC; отображаются в часовом поясе просматривающего пользователя. Психолог задаёт рабочие часы в своём часовом поясе |
| BR-SCHED-02 | Слот доступен для записи, если: попадает в рабочие часы психолога; не пересекается с другой сессией с учётом `P-BUFFER`; не попадает в отпуск/исключение; начинается не раньше `P-BOOK-MIN-LEAD` (или минимума психолога, если он больше) и не позже `P-BOOK-HORIZON` |
| BR-SCHED-03 | Длительность слота определяется форматом сессии; парная сессия занимает соответствующий интервал |
| BR-SCHED-04 | Отпуск не может быть сохранён, если в его период есть забронированные сессии: психолог должен сначала перенести или отменить их (с уведомлением клиентов). Система показывает список затронутых сессий |
| BR-SCHED-05 | Удержание слота на `P-SLOT-HOLD` при оформлении записи; параллельная попытка занять тот же слот получает отказ с предложением соседних слотов (гарантия отсутствия двойного бронирования) |
| BR-SCHED-06 | Запрос клиента «нет подходящего времени» содержит только окна (дни недели × время суток) и не содержит свободного текста; психолог может ответить открытием слотов или отклонить без объяснений |

## 5. Бронирование и сессии (`BR-BOOK`)

| ID | Правило |
|---|---|
| BR-BOOK-01 | Для бронирования необходимы: подтверждённый email, обязательные согласия, **привязанная карта с согласием на автосписание** — либо действующая корпоративная программа с доступным лимитом |
| BR-BOOK-02 | Цена сессии фиксируется в момент бронирования (уровень психолога, формат, промокод). Последующее изменение цены психолога не влияет на забронированные сессии |
| BR-BOOK-03 | Если бронирование сделано позже, чем за `P-CHARGE-OFFSET` до начала, оплата выполняется **синхронно в момент записи** (с 3-D Secure при необходимости); при отказе бронь не создаётся, слот остаётся удержанным до конца `P-SLOT-HOLD`, клиенту предлагается другая карта. Повторные попытки BR-PAY-05 к таким записям не применяются |
| BR-BOOK-04 | Клиент может иметь не более `P-BOOK-MAX-UPCOMING` предстоящих сессий у одного психолога одновременно и не более 1 сессии в один и тот же интервал времени |
| BR-BOOK-05 | Жизненный цикл сессии: `Забронирована → Ожидает списания → Оплачена → Идёт → Проведена`, с ветками `Отменена клиентом`, `Отменена психологом`, `Отменена системой (не прошла оплата)`, `Неявка клиента`, `Неявка психолога`, `Техническая проблема`, `Прервана`. **Перенос** — событие в истории сессии (статус не меняется, меняется время); **«Возврат оформлен»** — статус платежа, а не сессии; в интерфейсе они показываются дополнительными метками. Детально — [sequences_states.md](../06_architecture/sequences_states.md) |
| BR-BOOK-06 | Статус «Проведена» устанавливается психологом в форме итогов или автоматически, если оба участника были в комнате суммарно не меньше `P-AUTO-COMPLETE-MIN`, а психолог не заполнил итоги за `P-OUTCOME-DEADLINE` |
| BR-BOOK-07 | Сессия не продлевается при опоздании участника и заканчивается в плановое время |
| BR-BOOK-08 | Смена психолога клиентом не требует оплаты и не ограничена по количеству. Будущие сессии с прежним психологом клиент отменяет по общим правилам |
| BR-BOOK-09 | Парная сессия: второй участник до начала подтверждает участие и согласия на обработку ПДн по ссылке-приглашению с подписью кодом; без подтверждения он не допускается в комнату [ЮРИСТ] (Q-04) |

## 6. Отмена, перенос, неявка (`BR-CANC`)

| ID | Правило | Статус |
|---|---|---|
| BR-CANC-01 | Клиент отменяет или переносит сессию **бесплатно до момента списания** (`P-CHARGE-OFFSET` до начала) | [допущение] Q-05 |
| BR-CANC-02 | После списания отмена клиентом возвращает `P-LATE-CANCEL-REFUND` от суммы (по умолчанию 0 %); поддержка может принять индивидуальное решение (форс-мажор) с фиксацией причины | [допущение] Q-05 |
| BR-CANC-03 | Перенос после списания: в пределах `P-LATE-RESCHEDULE-LIMIT`, без доплаты и возврата; если нового времени не выбрано — действует BR-CANC-02 | [допущение] Q-05 |

## 7. Оплата и списания (`BR-PAY`)

| ID | Правило |
|---|---|
| BR-PAY-01 | Привязка карты — через платёжную форму провайдера (CloudPayments); ТЕТА не хранит и не обрабатывает реквизиты карт, только токен и маску |
| BR-PAY-02 | При привязке выполняется проверочная операция (авторизация на минимальную сумму с отменой или возвратом — по возможностям провайдера); клиенту заранее объясняется, что сумма вернётся |
| BR-PAY-03 | Согласие на автоматические списания фиксируется отдельно (дата, время, IP, версия правил) и отзывается удалением карты в любой момент (BR-PAY-08, BR-PAY-11) |
| BR-PAY-04 | Списание выполняется по токену за `P-CHARGE-OFFSET` до начала сессии (или сразу — BR-BOOK-03). Сумма = зафиксированная цена − скидка |
| BR-PAY-05 | При неуспешном списании: уведомление клиенту с ссылкой на замену карты; повторы по `P-CHARGE-RETRY`; при отсутствии оплаты к `P-CHARGE-DEADLINE` — сессия отменяется системой, слот освобождается, психолог и клиент уведомляются |
| BR-PAY-06 | Кассовые чеки (54-ФЗ) формируются через CloudKassir и отправляются на email клиента: «предоплата 100 %» — при списании; «полный расчёт» с зачётом предоплаты — после оказания услуги (статусы «Проведена», «Неявка клиента»); «возврат прихода» — при возврате. Ссылки на чеки доступны в CL-07. Признаки агента и данные поставщика — по решению Q-06 |
| BR-PAY-07 | Возврат выполняется на ту же карту; срок зачисления — по правилам банка; статус возврата отображается клиенту |
| BR-PAY-08 | Клиент может удалить карту в любой момент. Если есть предстоящие сессии, оплачиваемые с неё, система предлагает привязать другую карту; если карта не привязана к `P-CHARGE-DEADLINE`, такие сессии отменяются без удержаний, как отмена до списания (BR-PAY-11, 376-ФЗ) |
| BR-PAY-09 | Промокод применяется при бронировании; скидка фиксируется в сессии; один промокод на одну сессию; промокоды не суммируются между собой; корпоративная оплата имеет приоритет над промокодом |
| BR-PAY-10 | **[Рек., опция]** Двухстадийная схема: за 24 ч до начала сумма блокируется на карте (авторизация), за `P-CHARGE-OFFSET` — списывается (подтверждение). Неудачная блокировка даёт клиенту 12 ч на замену карты вместо 10. Так работает Ясно. Включается параметром `P-HOLD-OFFSET` (по умолчанию выключено — ТЗ говорит о списании за 12 ч); доступность и срок жизни блокировки зависят от CloudPayments |
