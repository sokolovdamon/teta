# ТЕХНИЧЕСКОЕ ЗАДАНИЕ на разработку сервиса онлайн-психологии «ТЕТА» (редакция 2)

> Сохранено в проект 11.09.2026 из сообщения заказчика. Текст приведён без изменений. Заменяет `prd.md` как основной источник требований; `prd.md` и `brief.md` сохраняются как исторические материалы.

## 1. НАЗВАНИЕ И СУТЬ ПРОЕКТА

1.1. Портал психологической помощи ТЕТА — сервис онлайн-психологии для проведения онлайн-сессий с психологами, автоматизации записи, проведения сеансов, выплат и аналитики, с функциями сопровождения пользователей и продвижения психологов.

1.2. Домен проекта: teta.su. Фирменный стиль, логотип, шрифты, фото- и видеоматериалы предоставляются Заказчиком.

1.3. Настоящее Техническое задание является неотъемлемой частью Договора № 07/09/2026 и основой для выполнения работ.

## 2. ЦЕЛИ СЕРВИСА

2.1. Для клиентов: подбор психолога по анкете и фильтрам; бронирование и оплата сессий с разовым добавлением карты и автоматическим списанием; проведение видеосессий; одностороннее сопровождение через рекомендации и дневники эмоций без канала связи с психологом вне сессий.

2.2. Для психологов: гибкое управление графиком; ведение базы клиентов; публикация собственных статей с автопостингом в «Яндекс Дзен» проекта ТЕТА; доступ к базе знаний и профессиональному сообществу.

2.3. Для владельца: управление пользователями и психологами; автоматизация выплат и аналитика; укрепление SEO за счёт авторского контента; развитие направления white-label B2B.

## 3. РОЛИ ПОЛЬЗОВАТЕЛЕЙ

- Клиент — получатель психологических услуг.
- Психолог — специалист, оказывающий услуги на Платформе.
- Администратор — сотрудник Заказчика: модерация публикаций, статей и отзывов, обработка обращений в модуле техподдержки, управление пользователями, контентом и выплатами.
- Супер-администратор — полный доступ, управление ролями и настройками Платформы.
- Супервизор — психолог с расширенными правами, проводящий супервизию.

3.1. Роли и права настраиваются средствами RBAC (этап 4) из административной панели без изменения кода.

## 4. ТЕХНОЛОГИЧЕСКИЙ СТЕК И ОКРУЖЕНИЯ

- Backend: Laravel 13.
- Frontend: Next.js 16, PWA.
- База данных: PostgreSQL 18.
- Кеширование и очереди: Redis.
- Видеосвязь: TetaMeet — модуль на основе собственной разработки Исполнителя DevMeet, стилизуемый под фирменный стиль Заказчика.
- Приём платежей: платёжный сервис, определяемый Заказчиком. Наименование сервиса, реквизиты подключения и документация предоставляются Заказчиком в процессе выполнения работ.
- Email-рассылки: собственная система рассылок Платформы (без использования сторонних сервисов рассылок). Отправка писем выполняется через SMTP-релей, реквизиты которого предоставляет Заказчик.
- Веб-аналитика: Яндекс.Метрика (счётчик предоставляет Заказчик).
- SEO: SSR или пререндеринг публичных страниц.
- Автопостинг статей: «Яндекс Дзен» проекта ТЕТА.

4.1. Разворачиваются окружения: разработки (dev), тестовое (stage), продуктивное (prod). Доступ Заказчика к тестовому окружению предоставляется с первого спринта.

4.2. Точные версии среды исполнения, СУБД и параметры хостинга фиксируются Сторонами до начала спринта 1 и признаются целевой программной конфигурацией для целей п. 8.3 Договора.

4.3. Оплата и предоставление доступов к сторонним сервисам (хостинг, домен, платёжный сервис, SMTP-релей, Яндекс.Метрика, «Яндекс Дзен») осуществляется Заказчиком (п. 14.1 Договора). Исполнитель выполняет интеграцию.

## 5. ТРЕБОВАНИЯ К УСТРОЙСТВАМ И БРАУЗЕРАМ

5.1. Основной формат работы Платформы — десктопный. Мобильная адаптивная вёрстка реализуется во всех интерфейсах Платформы, допускающих адаптацию.

5.2. С мобильных устройств доступны: просмотр сайта и профилей психологов, регистрация, запись на сессию, перенос и отмена сессии, просмотр личного кабинета.

5.3. Поддерживаемые браузеры: последние две версии Chrome, Safari, Firefox, Edge; мобильные Chrome и Safari. Контрольные разрешения для проверки адаптивной вёрстки: 360, 768 и 1440 пикселей по ширине.

5.4. Стиль подачи интерфейса — дружелюбный минимализм, на основе корпоративного стиля сайта teta.su.

## 6. ПОРЯДОК ВЫПОЛНЕНИЯ РАБОТ

6.1. Разработка ведётся по методологии SCRUM недельными спринтами. Состав и сроки спринтов определены Планом-графиком работ (Приложение 2).

6.2. По итогам каждого спринта Исполнитель предоставляет работающий инкремент на тестовом окружении и проводит демонстрацию в порядке п. 2.6 Договора.

6.3. Функциональные требования сгруппированы по этапам разд. 7 настоящего ТЗ; последовательность этапов согласована Сторонами.

## 7. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ ПО ЭТАПАМ

### Этап 1. Доработка дизайна

- Проработка пользовательских сценариев (CJM) и структуры экранов на основе действующих материалов проекта.
- Дизайн основного сайта (лендинга) с использованием корпоративного стиля, шрифта, логотипа, фото- и видеоматериалов Заказчика.
- Дизайн личного кабинета клиента в корпоративном стиле.
- Дизайн личного кабинета психолога в корпоративном стиле.
- Дизайн административной панели владельца ресурса в корпоративном стиле.
- Дизайн-система: палитра, типографика, сетка, библиотека UI-компонентов и их состояний.
- Проработка служебных состояний экранов: пустые списки, загрузка, ошибки, отсутствие прав доступа.
- Макеты шаблонов email-уведомлений.
- Согласование макетов с Заказчиком в порядке п. 2.6 Договора.

### Ядро Платформы (выполняется параллельно с этапом 1)

- Настройка окружений dev / stage / prod, репозитория, процессов сборки и развёртывания.
- Проектирование базы данных и структуры API.
- Регистрация по e-mail с подтверждением адреса, аутентификация, восстановление пароля.
- Базовая модель ролей (детализируется на этапе 4).
- Каркас SSR / пререндеринга публичных страниц для SEO.

### Этап 2. Разработка кабинета психолога

- Регистрация психолога и подтверждение квалификации: загрузка дипломов и сертификатов, статус проверки (на модерации / подтверждён / отклонён с комментарием).
- Заполнение профиля: фотография, опыт, образование, методы работы, специализации, стоимость сессии, описание.
- Настройка графика работы: рабочие интервалы, длительность сессии, перерывы, часовой пояс, отпуска и блокировка дат.
- Календарь записей: предстоящие и прошедшие сессии, перенос и отмена.
- Ведение карточек клиентов и приватных заметок психолога, недоступных другим специалистам.
- Просмотр динамики дневника эмоций клиента (функция клиента реализуется на этапе 3).
- Персональные рекомендации после сессии: прикрепление заданий, упражнений и материалов клиенту.
- Статистика и доход: проведённые сессии, начисления, история выплат, выгрузка отчёта.
- Управление автоматическим выводом средств на карту самозанятого.
- Email-уведомления психолога о новых записях, отменах и переносах.
- Запуск проведения видеосессий из кабинета средствами TetaMeet (реализация модуля — этап 3).

### Этап 3. Разработка кабинета клиента (бот-помощник «Герман» и живой администратор)

- Регистрация клиента по e-mail с подтверждением.
- Анкетирование для выявления потребностей; вторая опция — диалог с AI-ботом «Герман».
- Подбор психолога автоматически по результатам анкеты или бота либо вручную через каталог.
- Передача диалога живому администратору: подключение администратора к переписке, история диалога.
- Каталог и профили психологов: опыт, стоимость, специализации, отзывы; фильтры и поиск.
- Бронирование доступных слотов.
- Оплата через платёжный сервис, определяемый Заказчиком: разовое добавление карты, автоматическое списание за 12 часов до сессии, история платежей, возвраты по правилам Платформы. Интеграция выполняется после предоставления Заказчиком доступов и документации сервиса.
- Проведение видеосессий средствами модуля видеосвязи TetaMeet.
- Дневник эмоций: отметка эмоционального состояния при входе в личный кабинет (выбор эмодзи), история и динамика.
- Просмотр персональных рекомендаций и заданий, полученных от психолога.
- Возможность смены психолога и повторного анкетирования.
- Отзыв о специалисте с публикацией на странице психолога после модерации. Рейтинги психологов не реализуются.
- Email-уведомления и напоминания о сессии.

### Модуль видеосвязи TetaMeet (в составе этапа 3)

- Видеосессия «психолог — клиент» и групповые сессии для супервизии и интервизии.
- Развёртывание серверной части TetaMeet на инфраструктуре проекта, её настройка и стилизация интерфейса под фирменный стиль Платформы.
- Управление медиа: камера, микрофон, выбор устройства, демонстрация экрана.
- Текстовый чат внутри сессии, комната ожидания и допуск участников.
- Проверка оборудования перед входом, переподключение при обрыве связи, учёт фактической длительности сессии.

TetaMeet создаётся на основе модуля видеосвязи DevMeet, разработанного Исполнителем ранее и вне рамок Договора, путём его настройки и стилизации под требования Заказчика. Исключительные права на исходный код сохраняются за Исполнителем; Заказчику предоставляется безвозмездная бессрочная лицензия на его использование в составе Платформы, в том числе в режиме white-label, в порядке и на условиях п. 7.3 Договора.

### Этап 4. Разработка административной панели и RBAC

- Управление пользователями и психологами: поиск, фильтры, карточка пользователя, блокировка, смена роли, сброс пароля.
- Ролевая модель доступа (RBAC): роли, права, матрица «роль — раздел — действие», настройка без изменения кода.
- Премодерация публикаций, статей и отзывов.
- Финансовая аналитика: выручка, сессии, начисления психологам, комиссия Платформы.
- Настройка выплат психологам и правил автоматического вывода средств.
- Настройка сценариев и текстов email-уведомлений.
- Выгрузка отчётов по заданным фильтрам.
- Справочники: специализации, методы, темы обращений, типы услуг.
- Журнал действий пользователей (аудит) с фильтрацией по пользователю, разделу и периоду.
- White-label B2B: подключение стороннего партнёра, настройка наименования, логотипа, палитры и домена партнёра, добавление партнёром собственных психологов, раздельный учёт сессий и выплат по партнёру.
- Подключение и настройка Яндекс.Метрики.

### Этап 5. Разработка раздела супервизии

- Реестр супервизоров: профиль, направления, стоимость, расписание.
- Заявка психолога на индивидуальную или групповую супервизию.
- Запись на супервизию, подтверждение супервизором, проведение через модуль видеоконференций.
- Оплата супервизии либо её учёт в зависимости от настроек Платформы.
- Заключение (протокол) супервизора по итогам встречи.
- Учёт накопленных часов супервизии в профиле психолога и выгрузка справки.

### Этап 6. Разработка раздела интервизии

- Сообщество психологов: создание ветки обсуждения и экспертные комментарии коллег под ней.
- Модерация обсуждений и комментариев администратором.
- Интервизионные группы: состав, ведущий, периодичность встреч, лимит участников.
- Календарь встреч, самостоятельная запись участников, лист ожидания.
- Проведение групповых встреч через модуль видеоконференций.
- Протокол встречи и материалы, доступные участникам группы; учёт участия в профиле психолога.

### Этап 7. Модуль email-маркетинга

- Конструктор и библиотека шаблонов писем с переменными (имя, специалист, дата сессии, ссылка), предпросмотр и тестовая отправка.
- Формирование клиентских групп (сегментов) по фильтрам: активность, число сессий, тема обращения, дата регистрации, статус оплаты.
- Рекламные и маркетинговые рассылки: разовые, отложенные и триггерные (после регистрации, после сессии, при отсутствии активности).
- Настройка сценариев автоматической отправки уведомлений и маркетинговых материалов.
- Собственный механизм отправки: очередь рассылки на Redis, регулирование скорости отправки, повторные попытки при временных ошибках, отправка через SMTP-релей Заказчика.
- Обработка ошибок доставки: возвраты (bounce), жалобы на спам, автоматическое исключение недоставляемых адресов из последующих рассылок.
- Сбор статистики собственными средствами: пиксель отслеживания открытий и редирект-ссылки для учёта переходов.
- Ссылка на отписку в каждом письме, страница управления подпиской и учёт согласий на получение рассылок.
- Аналитика email-маркетинга: отправлено, доставлено, открытия, клики, отписки, жалобы; сравнение рассылок за период.

### Этап 8. Модуль создания и управления промокодами

- Типы промокодов: процентная скидка, фиксированная скидка, льготная первая сессия.
- Каузальные (массовые) и индивидуальные промокоды; генерация единичных и пакетных кодов, выгрузка списка.
- Параметры: период действия, общий лимит применений, лимит на одного пользователя, минимальная сумма.
- Ограничения по услугам, специалистам и сегментам клиентов.
- Применение промокода при оплате сессии.
- Статистика применения: число применений, сумма скидок, конверсия.

### Этап 9. Модуль написания, модерации и публикации статей

- Редактор статей для психологов: форматирование, изображения, цитаты, ссылки, автосохранение черновика.
- Отправка статьи на премодерацию, очередь модерации, комментарии модератора, возврат на доработку.
- Публикация, снятие с публикации, отложенная публикация.
- Автопостинг опубликованных статей в «Яндекс Дзен» проекта ТЕТА.
- Рубрики, теги, привязка к автору, SEO-поля (заголовок, описание, адрес страницы), SSR публичных страниц.
- Лента статей для клиентов: фильтры по рубрикам и авторам, поиск, похожие материалы, счётчики просмотров.

### Этап 10. Модуль «База знаний»

- Иерархия разделов и подразделов, порядок сортировки.
- Материалы: психологические техники, тесты, медитации, тексты аутотренингов; текст, изображения, файлы, аудио- и видеоссылки.
- Разграничение доступа по ролям: материалы для психологов, для клиентов, для администраторов.
- Полнотекстовый поиск и история изменений материала.

### Этап 11. Модуль техподдержки

- Виджет чата поддержки в кабинетах клиента и психолога (собственная реализация по механике, аналогичной Jivo).
- Рабочее место администратора в административной панели: обращения обрабатываются в той же роли, отдельная роль оператора поддержки не создаётся.
- Очередь обращений в административной панели: новые, в работе, ожидают ответа, закрытые.
- Назначение обращения администратору, передача другому администратору, внутренние комментарии.
- Переписка с вложениями и историей обращения, шаблоны быстрых ответов.
- Уведомления администратора о новом сообщении и клиента об ответе.
- Оценка качества ответа после закрытия обращения.

### Сквозные задачи

- Email-уведомления по событиям: регистрация, подтверждение записи, напоминание о сессии, списание оплаты, отмена и перенос, результат модерации, ответ поддержки.
- Логирование ошибок и действий пользователей, мониторинг доступности.
- Регрессионное тестирование, развёртывание на продуктивном окружении, подготовка документации.

## 8. НЕФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

- Обработка персональных данных в соответствии с Федеральным законом № 152-ФЗ; хранение данных на серверах на территории РФ.
- Передача данных по HTTPS; пароли хранятся в виде необратимых хешей; платёжные данные карт на стороне Платформы не хранятся (токенизация на стороне платёжного сервиса).
