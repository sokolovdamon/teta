# Утилиты документации ТЕТА

Python 3.9+, только стандартная библиотека (ничего устанавливать не нужно). Команды — из корня проекта.

| Утилита | Что делает |
|---|---|
| `build_mindmap.py` | Собирает mindmap в пяти форматах из одного markdown-источника |
| `check_docs.py` | Проверяет ссылки, ID требований и решений, открытые вопросы и маркеры во всём `docs/` |
| `render_diagrams.sh` | Рендерит исходники диаграмм `06_architecture/diagrams/*.mmd` в SVG в фирменном оформлении (Onest, цвета `#4D427A` и `#4A4A4A`) по конфигурации `mermaid_brand.json`; нужен Node.js, mermaid-cli запускается через `npx` |

---

## build_mindmap.py

```bash
# все форматы рядом с источником
python3 docs/_tools/build_mindmap.py docs/05_mindmap/teta_mindmap.md

# только часть форматов, в другую папку
python3 docs/_tools/build_mindmap.py docs/05_mindmap/teta_mindmap.md --formats html,mm --out-dir /tmp/mm

# только разбор: статистика по уровням, теги, предупреждения; код 1 при структурных ошибках
python3 docs/_tools/build_mindmap.py docs/05_mindmap/teta_mindmap.md --check
```

| Формат | Для чего |
|---|---|
| `.mm` | FreeMind 1.0.1 — Freeplane, импорт в XMind и MindManager. Корпоративные цвета ТЕТА, узлы глубже 3-го уровня свёрнуты |
| `.opml` | OPML 2.0 — универсальный импорт (XMind, OmniOutliner, Workflowy и др.) |
| `.mmd` | Mermaid `mindmap` — вставка в markdown (GitHub, Obsidian) |
| `.html` | Интерактивная карта (markmap-autoloader 0.18.12): масштаб, свернуть/развернуть, «Вписать в экран»; шрифт Onest. Нужен интернет (cdn.jsdelivr.net) |
| `.json` | Дерево `{text, tag, link, children}` для скриптов |

Сгенерированные файлы вручную не правим — меняем источник и пересобираем.

### Правила источника

```markdown
---
title: ТЕТА — карта платформы
---

# Платформа ТЕТА

## Кабинет клиента [Э3]

### Запись и оплата

- Выбор слота
  - Промокод [Э8]
- Документ ([Согласие на публикацию отзыва](https://teta.su/legal/review-consent))
```

- `title:` во front matter — заголовок HTML-страницы и OPML (необязателен; иначе берётся текст корня).
- Ровно один `# Корень`; `##`, `###`, `####` — уровни 1–3, без пропуска уровней (`#` → `###` — ошибка).
- Под заголовком — вложенные списки `- ` или `* `; отступ 2 или 4 пробела, единообразно по файлу.
- Разметка в тексте узла снимается: `**жирный**`, `*курсив*`, `` `код` ``; `[текст](url)` → текст, url становится ссылкой узла (в `.mm`, `.opml`, `.html`, `.json`).
- Тег этапа ТЗ в конце текста: `[Ядро]`, `[Э1]`…`[Э11]`, `[Сквозн.]`, `[11.1]`, `[Доп.]` (коды — [реестр решений](../01_inputs/decisions_v2.md), раздел 5). Тег остаётся в тексте, в `.mm` красит узел.
- Игнорируются пустые строки, `<!-- комментарии -->`, обычные абзацы, блоки кода.
- `--check` предупреждает о дублях среди соседних узлов, узлах длиннее 120 символов, пустых заголовках, неровных отступах.

## check_docs.py

```bash
python3 docs/_tools/check_docs.py                      # отчёт по docs/
python3 docs/_tools/check_docs.py --verbose            # все места ссылок и списки ID без внешних ссылок
python3 docs/_tools/check_docs.py --json > report.json # машиночитаемый отчёт
python3 docs/_tools/check_docs.py --root путь/к/docs --exclude 99_sources
```

Код выхода: `0` — ошибок нет, `1` — есть хотя бы один ERROR, `2` — не найдена папка `--root`.

| Проверка | ERROR | WARNING / INFO |
|---|---|---|
| Относительные ссылки в `*.md` (`[..](..)`, `![..](..)`, `[ref]: ..`, `<a href>`, `<img src>`) | файл не найден | якорь `#заголовок` не найден; регистр имени не совпадает |
| ID в `*.md` | дубль определения; ссылка на неопределённый ID | неверный формат (`FR-AUTH-01`); INFO — ID без ссылок из других файлов |
| ID в `*.xlsx` (все ячейки-строки) | ссылка на неопределённый ID, с листом и ячейкой | — |
| `01_inputs/open_questions.md` | — | число Q по P0/P1/P2 не совпадает со сводной таблицей; вопросы без приоритета; INFO — пропуски нумерации |
| Маркеры `TODO`, `TBD`, `???`, `(Q-NN)` | — | таблица по файлам |

Папка `_tools` не сканируется. Кириллица в именах файлов поддерживается (NFC/NFD macOS), но для новых файлов используем ASCII-имена.

## Конвенции ID

| Префикс | Формат | Пример | Где определяется |
|---|---|---|---|
| DEC | `DEC-NN` | DEC-01 | `01_inputs/decisions_v2.md` |
| FR | `FR-<МОДУЛЬ>-NNN` | FR-AUTH-001 | `04_project_docs/02_functional_requirements.md` |
| NFR | `NFR-<ОБЛАСТЬ>-NN` или `NNN` | NFR-SEC-01 | `04_project_docs/04_nonfunctional_requirements.md` |
| BR | `BR-<ОБЛАСТЬ>-NN` или `NNN` | BR-PAY-01 | `04_project_docs/03_business_rules.md` |
| INT | `INT-<СИСТЕМА>-NN` или `NNN` | INT-PAY-01 | `04_project_docs/05_integrations.md` |
| Q | `Q-NN` | Q-01 | `01_inputs/open_questions.md` |
| RISK | `RISK-NN` | RISK-01 | `04_project_docs/10_risks.md` |
| US | `US-<ЭПИК>-NNN` | US-CL-001 | бэклог |

`<МОДУЛЬ>` — заглавная латиница и цифры (`AUTH`, `PAY`, `B2B`); список модулей — [реестр решений](../01_inputs/decisions_v2.md), раздел 3.2.

**Определение** ID — ровно одно место в документации:

1. первая непустая ячейка строки таблицы: `| FR-AUTH-001 | Регистрация по email | ... |`;
2. начало заголовка: `### FR-AUTH-001 Регистрация по email`;
3. `**FR-AUTH-001**` в начале строки или пункта списка.

Любое другое упоминание — **ссылка**; у каждой ссылки должно быть определение.

- ID внутри блоков кода игнорируются (там обычно примеры), кроме блоков `mermaid`.
- Строку с `<!-- check_docs: ignore -->` утилита пропускает. Блок между `<!-- check_docs: off -->` и `<!-- check_docs: on -->` не проверяется.
- Открытые вопросы группируются по заголовкам с `P0` / `P1` / `P2`. Для вопросов вне таких разделов приоритет берётся из ячейки `P0`/`P1`/`P2` той же строки. Сводная таблица `| P0 | 4 |` сверяется с фактическим числом.
- Вопросы под заголовком, который начинается со слов «Решённые», «Закрытые» или «Снятые», не считаются открытыми и выводятся отдельной строкой «решено или снято».
- Настройки — в начале `check_docs.py`: `ID_PATTERNS`, `EXCLUDE_DIRS`, `ID_SCAN_CODE_LANGS`, `XLSX_DEFINITION_TYPES`. Например, `{"US"}` в `XLSX_DEFINITION_TYPES`, если user stories определяются только в `backlog.xlsx`.
